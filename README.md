# SkillSprint · AI-собеседование

Vue 3 + TypeScript + [Vite+](https://viteplus.dev/) нанофронтенд `interview`, версия `0.1.0`.
Экран по [Figma, Main / Собеседование начинается здесь](https://www.figma.com/design/yaXHM7qEsWFob4Zgcb1EwD/SkillSprint?node-id=13-773).
Боковое меню и переходы между разделами принадлежат корню SkillSprint.

## Локальная работа

Рекомендуемая среда: Node.js **26.12.0** из `.node-version` и npm **11.20.0**
из `packageManager`. Поддерживаемые версии Node: `^22.22.2 || ^24.15.0 || >=26.0.0`.
Минимальные версии учитывают Vite+, встроенный Vitest и jsdom.

```sh
npm ci
npm run dev
```

Открыть http://localhost:5173. Локальная страница вызывает тот же `mount`,
что и корневой загрузчик. Dev-сервер разрешает CORS для localhost/127.0.0.1:8099.
Другие локальные origins добавляются явно в `vite.config.ts`.

```sh
npm run check         # vp check: форматирование, Oxlint и типы; затем vue-tsc и Vue-шаблоны
npm run format        # Oxfmt: форматирование проекта
npm run format:check  # проверка форматирования без изменения файлов
npm test              # Vitest: один запуск всех автоматических тестов
npm run test:watch    # тесты с перезапуском при изменениях
npm run test:coverage # тесты и отчёт покрытия в coverage/index.html
npm run build:prod    # dist/index.js — UMD-приложение для прямого запуска через BroJS
npm run build:brojs   # псевдоним build:prod
npm run build:nano    # dist-nano/index.js — ESM-модуль для загрузчика корня SkillSprint
npm run build:demo    # dist-demo/ — отдельная страница для демонстрации
npm run preview       # просмотр готовой демосборки
npm run verify        # все проверки, покрытие и три сборки; та же команда используется в CI
```

Vite+ 1.4.0 установлен локально и закреплён в `package.json` и lock-файле.
Глобальный `vp` не требуется: npm-скрипты используют локальный бинарник.
Можно вызывать команды напрямую: `npm exec -- vp dev`, `npm exec -- vp check`,
`npm exec -- vp test`. При установленном глобальном CLI доступны те же `vp dev`,
`vp check`, `vp test` и `vp run verify`.

Настройки сборки, Oxlint, Oxfmt и Vitest находятся в `vite.config.ts`.
Отдельный `eslint.config.js` сохраняет исходные проверки Vue-шаблонов,
которые Oxlint пока не поддерживает. `vue-tsc` проверяет типы внутри `.vue`;
сгенерированный `src/env.d.ts` нужен TypeScript-проверке самого Vite+.
Прежние настройки Prettier перенесены в Oxfmt: без точек с запятой,
одинарные кавычки, ширина строки 100 символов.

Сборки BroJS и нано не являются HTML-приложениями: их подключают соответствующие загрузчики.
Для просмотра через `preview` сначала нужна `build:demo`.

## Публикация на стенд

### Через панель BroJS без доступа к серверу

Проверенный лог штатного pipeline содержит `VERSION=main npm run build:prod`.
Скрипты из `https://gitverse.ru/bro.js/jenkins-scripts.git` затем переносят `dist/*`
в каталог версии и публикуют его рекурсивно. В старой сборке Interview был только один JS-файл.
`build:prod` поэтому создаёт **один самодостаточный UMD-файл `dist/index.js`**,
совместимый с внешним fire.app/SystemJS. Команды Jenkins менять не требуется:
отправьте изменения в Git и повторите сборку через панель проекта `skillsprint-Interview`.

Локальное воспроизведение команды стенда и проверка готового артефакта:

```sh
npm ci
VERSION=main npm run build:prod
node scripts/check-brojs-build.mjs
```

В панели Interview сохраняются навигация `skillsprint-Interview.main` и значение
`/skillsprint-Interview`; опубликованный файл остаётся `index.js` в каталоге `main`.
Вкладки «Навигация», «Конфиг», «Фичи» задают значения для приложения во время запуска,
а формат JS задаётся кодом сборки в репозитории.

`src/brojs.ts` адаптирует `mount(component, element, { push })` и отдельный `unmount()`
к контракту нано. Для автономного запуска контекст использует `/interview`, `/api`,
`user: null`, а навигацию передаёт в BroJS `push`.
Проверка артефакта выполняет UMD через AMD и глобальную переменную, затем монтирует
экран и проверяет очистку. Vue, стили, шрифты и изображения включены в JS.

Прежняя ESM-сборка заканчивалась `export { ... }`. Внешний загрузчик стенда
не разбирает этот файл как native ES-модуль, что приводило к `Unexpected token 'export'`.
Сообщение «Файл JENKINS не существует. Уведомление не отправлено» относится
к отправке уведомлений pipeline и не объясняет синтаксическую ошибку в браузере.
После публикации проверьте новый файл в Network с отключённым кешем.

### Через корень SkillSprint

Для конфигурации `config/nano-sources.json`, где interview подключён как нано,
нужна **ESM-сборка**, а не UMD для прямого запуска. При переходе на эту версию
Interview измените его запись в корне: `scripts.build: "build:nano"`,
`output: "dist-nano"`, `entry: "index.js"`. Обновите фиксированный ref на версию,
содержащую новый скрипт. Не применяйте новый скрипт к старому тегу без него.
В **корневом репозитории SkillSprint** выполните:

```sh
npm ci
npm run build:integrated
```

Корню нужен SSH-доступ к Git-репозиторию interview и существующий фиксированный
`source.ref`. Значение `refs/tags/v0.1.0` собирает именно тег: последующие push
в `main` его не обновляют. Для нового кода укажите новый релизный тег с согласованной
версией либо полный commit SHA, сохранив совпадение версии пакета с конфигурацией.

Опубликуйте **весь `dist/` корня** с сохранением структуры:

```text
dist/
  index.js
  nanos.json
  release.json
  nanos/interview/0.1.0/index.js
  ...остальные ресурсы корня
```

В BroJS запускается корневое приложение `skillsprint`; затем его загрузчик читает
`nanos.json` и импортирует ESM interview через native `import()`.
На стенде включите `skillsprint → ai-interview → value: "true"`.
Локально флаг задаётся в `bro.config.js`; на стенде значения предоставляет BroJS.
`publicPath` корня должен соответствовать фактическому URL ресурсов. Если реестр
опубликован отдельно, задайте его полный URL через BroJS-конфигурацию `skillsprint.nanos`.

При текущих трёх `source: null` используйте именно `build:integrated`:
он пропустит отсутствующие модули. `build:release`/`FULL_RELEASE=true` требует
все четыре источника, а `build:prod` корня создаёт пустой реестр без interview.
Публикации одного `index.js` для этого варианта недостаточно, но штатный pipeline
поддерживает передачу всего `dist`: `predeploy/Jenkinsfile` переносит `dist/*`,
а `groovy/deploy.groovy` публикует `<version>/**` без flatten.
Поскольку панель всегда вызывает `build:prod`, в корневом `package.json` для
интегрированной публикации этот скрипт должен вызывать `npm run build:integrated`.
Текущий `build:integrated` не вызывает `build:prod`, поэтому рекурсии не будет.

Отдельно проверьте доступ Jenkins к Git-источнику: текущая схема корня принимает
только SSH-адреса, а штатный pipeline из лога клонирует основной репозиторий по HTTPS.
Успешное клонирование основного репозитория не подтверждает SSH-доступ к interview.
Если SSH-ключа у Jenkins нет, понадобится изменение схемы корня для публичных
HTTPS Git-адресов либо настройка учётных данных владельцем Jenkins.

При проверке стенда 26.10.2026 реестр
`https://static.brojs.ru/skillsprint/main/nanos.json` существовал, но содержал пустой
`nanos`. Для этой версии корня на вкладке «Конфиг» проекта `skillsprint` можно явно
задать префикс `skillsprint`, ключ `nanos`, значение
`https://static.brojs.ru/skillsprint/main/nanos.json`.
Это исправляет выбор адреса; сам реестр заполнится только после интегрированной сборки.

## Деморежим

Три вопроса: замыкания, асинхронность и границы модулей. После ответа показываются
найденные ключевые слова, темы для самопроверки и пример объяснения. Затем можно
перейти дальше, посмотреть итог с собственными ответами и заданиями для повторения,
начать заново. Пустые ответы не принимаются; лимит локального демо — 5000 символов.
Enter или Ctrl/Cmd+Enter отправляет ответ; Shift+Enter добавляет новую строку.
После разбора Enter открывает следующий вопрос, а после последнего — итог.
Во время ожидания повторная отправка блокируется.

Это локальная демонстрация, без вызовов AI или сохранения на сервере.
Совпадения слов не являются оценкой правильности. Баллы нейросети не имитируются.
Дата в шапке соответствует сегодняшнему дню в часовом поясе браузера и обновляется
в полночь, а также при возвращении на страницу. Пока API активности не подключён,
серия показана как «Серия: —»: отсутствие данных не подменяется нулём.
Предлагаемый контракт и правила расчёта серии описаны в [docs/activity-api.md](docs/activity-api.md).
Состояние принадлежит одному подключению и очищается при unmount/перезагрузке.

## Контракт и интеграция

`src/index.ts` экспортирует `contractVersion = 1` и `mount(element, context)`.
Результат содержит идемпотентный `unmount()`. Контекст и контейнер проверяются
общим `@skillsprint/contracts@1.0.0`. Vue, Goober и Zod включены в bundle;
отдельных CSS-файлов и внешних импортов npm-пакетов нет.

В `vendor/skillsprint-contracts-1.0.0.tgz` находится готовый пакет из корня
SkillSprint, а не копия исходных схем. Архив входит в репозиторий, поэтому `npm ci`
не требует абсолютного пути к соседнему проекту. При обновлении контракта заменяется
официальный архив и lock-файл. В дальнейшем можно перейти на согласованный npm-реестр.

Для локального реестра корня используется запись:

```json
{
  "schemaVersion": 1,
  "nanos": {
    "interview": {
      "version": "0.1.0",
      "contractVersion": 1,
      "entry": "http://localhost:5173/src/index.ts",
      "styles": []
    }
  }
}
```

Существующие записи остальных нано нужно сохранить. Корень запускается с
`NANO_REGISTRY_FILE=config/nanos.dev.json`; раздел `/interview` должен быть включён
его feature flag. Для выпуска нано используются `output: "dist-nano"`, `entry: "index.js"`,
`styles: []`, скрипты `check` и `build:nano`, версия `0.1.0` и фиксированный Git ref.
Адрес Git и публикация задаются владельцем корня. Изменений BroJS/Webpack здесь нет.

DOM, font-face и Goober style-тег создаются в переданном контейнере. При отключении
Vue размонтируется, ожидающий демо-запрос отменяется, контейнер экземпляра удаляется.
Несколько экземпляров получают отдельные состояния, стили и DOM-id.
Адаптивность зависит от ширины контейнера нано, а не от ширины окна корня.

## Тесты и CI

`npm test` запускает встроенный в Vite+ Vitest 5.0.5 с jsdom. Проверяются:

- схемы и разбор ответа, отмена запросов и обработка ошибки с сохранением черновика;
- Enter, Ctrl/Cmd+Enter, Shift+Enter, IME, защита от повторной отправки;
- три вопроса, итог, повторная тренировка и перенос фокуса;
- независимость двух подключений, уникальность DOM-id, собственные стили,
  отмена запроса и очистка таймеров при unmount, повторный mount/unmount;
- текущая дата, локальная полночь, возвращение на вкладку, часовые пояса и DST.

Время в тестах управляемое: тесты не ждут настоящую полночь или задержку демоответа.
Исходные 9 тестов перенесены с `node:test` без потери проверок.
Покрытие V8 сохраняется как HTML, LCOV и JSON summary. Обязательные пороги:
90% строк/выражений/функций и 80% ветвей. Из измерения исключены только
точка локального запуска `src/main.ts`, декларации и файлы, содержащие только типы.

GitHub Actions в `.github/workflows/ci.yml` запускается на push и pull request:
чистая установка через `npm ci`, затем `npm run verify`, включая BroJS-сборку
и проверку загрузки UMD через AMD и глобальную переменную. Конфигурация подготовлена
для репозитория; удалённый CI выполняется после отправки изменений на GitHub.

### Дополнительная проверка в настоящем браузере

После `build:nano` и запуска dev-сервера открыть `/tests/browser.html`.
Кнопки проверяют исходный и собранный ESM-модуль: форму v1, два одновременных
подключения, изоляцию состояния/стилей, отмену ожидающего ответа, повторный unmount,
повторный mount и отказ при некорректном контексте. Там же есть превью 819px/375px.
Эта служебная страница не входит в production-сборку нано или демо.
Настоящий корень и внешний стенд BroJS проверяются отдельно.

## Структура

`src/index.ts` — адаптер v1; `src/main.ts` — локальный запуск.
`src/pages/interview` — Vue-экран и его `styles.ts`.
`src/features/interview` — схемы, выведенные типы, демо-вопросы, адаптер ответа
и состояние одного подключения. `src/shared/styles` — токены и локальные font-face.
Иконки Flame, Sparkles и Send взяты из [Lucide](https://lucide.dev/guide/vue/)
(`@lucide/vue`) и встроены в bundle. Неиспользуемые SVG из Figma и стартового шаблона удалены.
Inter поставляется локальным npm-пакетом,
без сетевых запросов к CDN. Тесты находятся в `tests`.
