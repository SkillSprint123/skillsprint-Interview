# API интервью

Сверено 23 октября 2026 года с `http://localhost:8080/swagger/openapi.json`.
Актуальный сервер — Go + Gin + PostgreSQL. Старые общие документы описывали Express;
этот нано не создаёт второй сервер и не обращается к GigaChat напрямую.

| Действие                           | Запрос                                                                                   | Успешный ответ                      |
| ---------------------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------- |
| Создать сессию по сохранённой цели | `POST /api/interview-sessions`, тело `{}` либо `{"mode":"demo"}` / `{"mode":"gigachat"}` | 201, `InterviewSession`             |
| Получить сессию и результат        | `GET /api/interview-sessions/{id}`                                                       | 200, `InterviewSession`             |
| Ответить на текущий вопрос         | `POST /api/interview-sessions/{id}/answers`, тело `{"question_id":1,"answer":"..."}`     | 200, обновлённая `InterviewSession` |

JSON использует snake_case. `InterviewSession` содержит `id`, роль/уровни, `mode`,
`status: active | completed`, даты, `total_questions`, `answered_questions`,
`current_position`, nullable `average_score` и массив `questions`.
Вопрос содержит числовые `id`/`position`, `text` и nullable `answer`, `feedback`,
`score`, `answered_at`. В сессии ровно три вопроса. Серверный лимит ответа — 10000
символов; локальное демо пока ограничивает ответ 5000 символами.

В серверном `demo` ответы сохраняются, но `score` и `average_score` остаются null.
Интерфейс должен показывать отсутствие оценки, не заменять null нулём.
Настоящая оценка появляется только при работе серверного `gigachat`.

Для старта нужна сохранённая цель: без неё сервер возвращает 409.
Ответы принимаются по порядку. Точный повтор уже принятого ответа возвращает
текущее состояние, изменение принятого ответа — 409. Ошибка провайдера не сохраняет
ответ и не продвигает сессию. После сетевого сбоя нужно сначала восстановить сессию,
чтобы выяснить, был ли ответ принят; нельзя автоматически создавать новое интервью.

Ошибки содержат `{ "error": "..." }`. Для UI нужны состояния 400 (данные),
401 (авторизация), 404 (сессия недоступна), 409 (цель или конфликт состояния),
503 (AI недоступен), 504 (таймаут), 500 (ошибка сервера).

Все `/api` требуют `Authorization: Bearer TOKEN`; это API-токен, не JWT.
Пользователя определяет сервер. Swagger допускает отдельно включённый серверный
`DEV_USER_ID` для локальной работы, но это не клиентский механизм авторизации.

Перед подключением нужно согласовать доставку авторизации корнем/BFF.
Контракт v1 содержит `apiBaseUrl`, но не Bearer-токен и не авторизованный fetch.
Его нельзя незаметно расширять или передавать токен через URL/localStorage
как обход этого решения. Секрет провайдера GigaChat остаётся только на сервере.
Нужны также локальный proxy/CORS и согласованный API base URL.

Сейчас экран использует только локальный `demo-service.ts`. Сетевые запросы,
сохранение/восстановление серверной сессии и серверная авторизация не включены.
