# Дата и серия занятий

Это предлагаемый контракт для бэкенда, а не описание уже существующего эндпоинта.
Текущий экран использует локальное демо и не отправляет запросы активности.

## Текущая дата

Для даты отдельный запрос не нужен. Фронтенд показывает текущий день через
`Intl.DateTimeFormat('ru-RU')` в часовом поясе браузера. Дата обновляется в местную
полночь и при возвращении на страницу. Например: «Суббота, 24 октября».

Часовой пояс для запроса серии берётся из
`Intl.DateTimeFormat().resolvedOptions().timeZone`. Дата и серия должны использовать
один и тот же пояс.

## 1. Получить серию

Добавить один новый запрос:

```http
GET /api/me/activity?time_zone=Europe%2FMoscow
Authorization: Bearer TOKEN
```

`time_zone` — обязательный IANA-пояс. Сервер проверяет его, пользователя берёт
из авторизации. Фронтенд не передаёт `user_id`, сегодняшнюю дату или длину серии.

Пример ответа `200 OK`:

```json
{
  "time_zone": "Europe/Moscow",
  "as_of_date": "2026-10-24",
  "current_streak": 7,
  "longest_streak": 12,
  "practiced_today": false,
  "last_activity_date": "2026-10-23"
}
```

- `as_of_date` — сегодняшний календарный день по серверному времени в указанном поясе.
- `current_streak` — текущая серия последовательных дней, целое число от 0.
- `longest_streak` — максимальная серия за всю историю, целое число от 0.
- `practiced_today` — был ли уже засчитан сегодняшний день.
- `last_activity_date` — последний засчитанный календарный день либо `null`.
- Все даты имеют формат `YYYY-MM-DD`, без времени.

Пользователь без истории получает `current_streak: 0`, `longest_streak: 0`,
`practiced_today: false`, `last_activity_date: null`. Ошибка сети или сервера
не означает нулевую серию: в интерфейсе в этом случае показывается «Серия: —».

Ошибки: `400` — отсутствующий или неизвестный пояс, `401` — нет авторизации,
`500` — ошибка сервера. Формат ошибки: `{ "error": "..." }`.
Ответ персональный: `Cache-Control: private, no-store`.

## 2. Засчитать день практики

Отдельный клиентский `POST /activity` не нужен. Предлагаемое правило: день
засчитывается при первом успешно сохранённом ответе на вопрос интервью.
Для этого используется уже существующий запрос:

```http
POST /api/interview-sessions/{id}/answers
Authorization: Bearer TOKEN
Content-Type: application/json

{
  "question_id": 1,
  "answer": "Замыкание сохраняет доступ к внешним переменным…"
}
```

Бэкенд записывает факт практики в той же транзакции, что и принятый ответ,
используя серверный `answered_at` в UTC. Для одного ответа событие создаётся
не более одного раза: уникальный ключ источника — ID принятого ответа.
Повтор того же запроса возвращает существующий ответ, не создаёт новую активность
и не переносит её на дату повторной отправки. Неуспешный запрос и просмотр
страницы день не засчитывают. Сохранённые ответы в серверном `demo` и `gigachat`
засчитываются одинаково; локальное демо без сохранения на сервере — нет.

Для текущего интерфейса этого достаточно. Если позже серия станет общей для
заданий, уроков и интервью, аналогичные события создают их серверные обработчики.
Клиент по-прежнему не назначает себе день практики.

## Правила расчёта

1. Взять текущее серверное время, перевести в `time_zone` и получить `as_of_date`.
2. Перевести UTC-время каждого события практики в тот же пояс и выделить
   уникальные календарные даты. Несколько ответов за день дают один день.
3. Если последняя дата — сегодня или вчера, посчитать последовательность
   календарных дней назад от неё. Это `current_streak`.
4. Если последняя дата раньше вчерашней, текущая серия равна 0.
5. `longest_streak` — самая длинная последовательность во всей истории.

Серия сохраняется утром нового дня, даже если пользователь сегодня ещё не занимался.
Она обнуляется только после полного пропущенного календарного дня.
Используются календарные даты, а не интервалы по 24 часа: это учитывает смену
месяца, года и переходы летнего времени. При смене `time_zone` история
пересчитывается в запрошенном поясе по исходным UTC-меткам.

Для PostgreSQL источником может быть таблица событий с `user_id`,
`source_answer_id UNIQUE`, `occurred_at TIMESTAMPTZ`. Нужен индекс
`(user_id, occurred_at)`. Локальная дата получается из
`(occurred_at AT TIME ZONE :time_zone)::date`. Наивного `current_streak += 1`
в обработчике ответа недостаточно: длина серии зависит и от текущей даты.

## Обновление на фронтенде

Запрашивать серию при открытии экрана, после успешного сохранения ответа,
в местную полночь и при возвращении на вкладку. Повторные запросы можно объединять.
Не увеличивать счётчик оптимистично на каждый ответ.

Текст счётчика: «1 день подряд», «2 дня подряд», «5 дней подряд»,
«11 дней подряд», «21 день подряд», «22 дня подряд». При 0 — «Начни серию сегодня».
Число и склонение определяются по `current_streak` (например, через
`Intl.PluralRules('ru')`). До успешной загрузки и при ошибке — «Серия: —».

До подключения API нужно согласовать авторизованный запрос через корень/BFF:
в текущем контракте v1 нет токена или авторизованного `fetch`, см.
[backend.md](backend.md). Токен не следует добавлять в URL или локальное хранилище.
